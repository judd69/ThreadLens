ThreadLens
Your JVM froze. Which thread did it?

A zero-dependency Java CLI that X-rays a jstack dump: deadlocks, lock contention, wait chains and stuck threads — in seconds, offline, with a report you can hand to anyone.

View on GitHub See a real sample report → 
jstack <pid> > dump.txt
java -jar threadlens.jar dump.txt --format html --output report.html

What it finds

Deadlocks, for real

Builds its own wait-for graph and finds lock cycles — even when the JDK's deadlock footer is missing.

Most contended lock

Every lock with holder, class and waiter list, most-contended first. 3+ waiters = a CONTENTION verdict.

Wait chains

For each stuck thread, the full chain of holders it is waiting behind — not just its own stack.

States & hot frames

RUNNABLE / BLOCKED / WAITING counts, daemon split, and the top-of-stack methods your threads are actually in.

CI-ready

--fail-on deadlock or --fail-on blocked exits 1, so a stuck service fails the gate, not the on-call.

Three report formats

Coloured terminal text, JSON for scripts, and a single self-contained HTML file — no server, no upload.

Build & test

./build.sh   # compiles, runs 24 JUnit 5 tests, builds threadlens.jar,
             # regenerates docs/sample-report.html
java -jar build/threadlens.jar examples/deadlock.txt

Requirements: Java 17+. No dependencies at runtime — the jar is plain javac output. ThreadLens never uploads your dump; HTML reports are single self-contained files.
